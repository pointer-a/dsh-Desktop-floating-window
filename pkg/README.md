# dsh-taskbox —— 桌面任务浮窗

把 DSH 放到后台干活时，桌面上留一个**始终置顶的小方框**：实时看每个对话在跑什么、几个在等确认；
需要**工具授权**或 **`ask_user_question` 选择**时，直接在小窗里点选确认；点一下就能把 DSH 主窗口唤回前台。

```
┌──────────────────────────────────────────┐
│ ● 任务   1 待确认 · 3 进行中 · 12 对话   ⤢ ✕ │
├──────────────────────────────────────────┤
│ ▌● 写一个桌面任务浮窗插件      等待授权    │
│  ● 离线包签名校验失败排查      12 分钟     │
│  ● 整理 OpenViking 记忆条目    48 分钟     │
├──────────────────────────────────────────┤
│  需要授权           写一个桌面任务浮窗插件  │
│  允许执行以下命令吗？                      │
│  ┌────────────────────────────────────┐  │
│  │ bash · rm -rf dist && pnpm build   │  │
│  └────────────────────────────────────┘  │
│  [ 允许一次 ]            [ 拒绝 ]         │
└──────────────────────────────────────────┘
```

## 它是什么、为什么这么实现

- **Host 半区**（本包 `lib/`）跑在 DSH 的 Host 进程里：把「哪个对话在跑 / 在做什么 / 谁在等确认 / 等的是什么」
  压成一份 1 秒刷新的状态快照，并通过只监听 `127.0.0.1` 的临时端口 + 每次启动随机 token 暴露给小窗。
- **小窗**（`assets/minibox/minibox.ps1`）是一个**独立**的 PowerShell + WPF 进程：无边框、圆角、置顶、不进任务栏。
  它只认协议，不认 DSH。
- 为什么不用浏览器里的面板：DSH 的 Web GUI 一旦最小化/切走，页面里的浮层就看不见了；而 Host 插件进程
  **不能创建 OS 窗口**（Electron 的 `BrowserWindow` 只有桌面壳能建），所以真正跨应用置顶只能由 Host
  spawn 一个独立窗口进程 —— 这也是本插件的核心取舍。

协议（两份实现的唯一契约）见仓库里的 `docs/PROTOCOL.md`。

## 交互

| 操作 | 行为 |
|---|---|
| 拖动标题栏 | 移动窗口；松手后位置写进 `$DSH_HOME/task-box/window.json` |
| 双击标题栏 / 点折叠 | 折叠成 320×44 的一行摘要；有待确认时标题栏琥珀色呼吸 |
| 点某一行对话 | 把 DSH 主窗口 `SW_RESTORE` + 置前 |
| `⤢` | 同上（唤回主窗） |
| `✕` | 关闭小窗（Host 记下「用户主动关闭」，不再自动弹回；有新确认时会再弹一次） |
| 小窗里点「允许一次 / 拒绝」 | 直接对该次授权作答 |
| 小窗里点选项 / 勾选后「提交」 | 直接回答 `ask_user_question` |
| DSH 里输入 `/taskbox` | 手动唤回小窗（关掉之后用这个） |

窗口高度随内容自适应（最少「标题栏 + 2 行」，最多 6 行；有待确认卡片时固定最高），
列表在超过 6 行时内部滚动。

### 「小窗优先」的确认时序（重要）

DSH 的确认是**一次转发下来的请求**：浏览器那张卡只在它自己那次 RPC 结算后才会消失。
所以本插件在小窗运行时采用「小窗优先」：

1. 小窗在跑 → 先只把请求显示在小窗里，**默认 20 秒内不转发**给 DSH 浏览器界面；
   在这段时间内作答，主窗口不会出现确认卡（也不会留下「小窗答完了、主窗口还在」的孤儿卡）。
2. 20 秒内没人答 / 小窗没在运行（冷启动时再加 8 秒）→ 再转发给 DSH，两边都能答，谁先答都算数。
3. 如果已经转发之后你才在小窗作答，DSH 主窗口那张卡可能滞留到该轮工具结束（客户端行为）。

宽限期可用 `DSH_TASKBOX_FORWARD_DELAY_MS` 调整（`0` = 立刻转发，行为同纯浏览器确认）。

## 安装（桌面端）

### 通过插件市场

DSH 侧边栏 → **插件** → **更多** → 启用「自定义插件市场」→ **发现** → 添加索引源：

```
https://pointer-a.github.io/dsh-Desktop-floating-window/v1/plugins.json
```

然后在列表里安装本插件（市场会从 npm 装 `dsh-taskbox@<version>`）。

### 手动安装

桌面端读的是 **`desktop` profile**，`dsh plugin --profile desktop` 被设计性拒绝。正确姿势是在桌面端会话里让
宿主自己装：用当前宿主内置的 `plugin_manager`，`install_bundle` 的 `target` 填 npm 包名：

```
plugin_manager  action: install_bundle  target: "dsh-taskbox"
```

本地开发时也可以把 `target` 换成仓库里 `pkg` 目录的绝对路径（`link:` 方式，改代码即时生效，但移动目录后要重装）。

装完如果浮窗没有立刻出现，完全退出客户端（含托盘）再打开。卸载用 `remove_bundle`，`target: dsh-taskbox`。

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `DSH_TASKBOX_AUTOSTART` | `1` | 设为 `0` 时 Host 不自动拉起小窗（仍可用 `/taskbox` 或 `plugin_manager` 重新启用） |
| `DSH_TASKBOX_FORWARD_DELAY_MS` | `20000` | 小窗运行时，先把确认留在小窗多久再转发给 DSH 浏览器界面（`0` = 立刻转发） |
| `DSH_TASKBOX_DEBUG` | 未设 | 设任意值则把插件日志同时打到 Host 的 stdout |

## 数据放在哪（全部在本机）

| 文件 | 内容 |
|---|---|
| `$DSH_HOME/task-box/server.json` | 当前本地服务端口 + token（Host 退出时删除） |
| `$DSH_HOME/task-box/window.json` | 小窗位置与折叠状态 |
| `$DSH_HOME/task-box/host.log` | Host 半区日志（排障第一现场） |
| `$DSH_HOME/task-box/minibox.log` | 小窗进程 stdout/stderr（含窗口内异常堆栈） |

`$DSH_HOME` 未设置时回退到 `%USERPROFILE%\.dsh`。

**隐私边界**：本地 HTTP 只绑 `127.0.0.1`，每次 Host 启动重新生成 token；不联网、不读凭据、
不写任何 DSH 之外的位置；日志里只有会话标题、工具名与命令片段。

## 已知限制

- 只支持 Windows（WPF + Win32 窗口唤醒）。
- DSH 重启后由新 Host 重新拉起小窗；Host 崩溃时小窗会在连续失败后退化为「离线」并自动退出。
- 一次 `ask_user_question` 里带**纯文本输入**的问题无法在小窗作答（小窗没有输入法环境），
  卡片会提示「去主窗口回答」。
- 小窗内的确认与 DSH 里的确认是**同一条请求的两个入口**：你在哪边先答，另一边随工具结果消失。
